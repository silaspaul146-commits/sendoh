# Foundation decisions

## Source precedence

Latest explicit user instructions override older documents. The accepted business definition supplies optional targets and free coordination. Requirements, PRD, UX Architecture and Brand System supply their respective rules. UI boards supply visual references but do not override later decisions.

## Scope

Flutter organizer, guest web, FastAPI and PostgreSQL. Requests and P2P Pay are included in the first release after collection implementation. Cash registration occurs at final reconciliation; settlement fees are paid from eligible collection funds. No user-facing reversal workflow.

## This increment

Implemented only collection creation and viewing. Home/Activity/Profile navigation. Teal primary, warm background, orange creation action with dark text. Native platform scaffolding is generated by the bootstrap script.

Development identities deliberately replace OTP ONLY for local development; this is not a production identity design. Backend startup refuses environments other than explicitly selected development. Production auth must replace this boundary before release.

Modes ANY_AMOUNT, EXPECTED_TOTAL and MINIMUM_TOTAL implement the previously proposed schema default. Minimum means cumulative expected participation, not a per-payment rule; no payments exist yet. These choices remain reviewable before payment implementation.

Creation can save DRAFT or atomically publish ACTIVE. The Flutter flow publishes directly. Editing/publishing an existing draft is not yet exposed. Targets and deadlines can be omitted. Deadlines are stored with timezone information; they have no automatic close behavior.

One public token per collection. Public views show collection data and organizer display name only, not the participant roster. Guest participant claiming remains unresolved.

Financial amounts are integers. The collected total is explicitly zero because this increment has no financial records; replace it with the authoritative contribution projection when that module is built.

## Open decisions

- OTP provider, real user session security and credential recovery.
- Guest participant identity and historical-record access.
- Request guest verification and pay-on-behalf rules.
- CamPay contract, callback authentication, idempotency and delivery semantics.
- P2P/Request pricing and funded-but-undelivered recovery.
- Reopening, post-payment changes and correction policies.
- Production mobile package ID, hosting and deployment configuration.

Do not expose real payment controls until provider integration, reconciliation and authorization have been tested.
